3. Four-color visual transmitter

Turn the RPR1 binary stream into a sequence of custom 2D visual codes. Each data cell represents two bits using four colors; every frame includes a header, index, total, length, CRC-32 checksum for the fragment, and checksum for the complete stream.

A larger grid increases the bytes per image, but makes each cell physically smaller and scanning more sensitive to focus, distance, and screen quality. The transmitter and receiver must use the same size.
More overhead increases tolerance for lost frames, but makes the sequence longer.
Set the sequence speed (1–60 FPS). Actual speed may be lower if the browser or display cannot keep up.

4. Camera-based visual receiver

Point the camera at the Q4R1 sequence displayed on screen. Continuous scanning captures frames automatically, ignores duplicates, and measures actual throughput. You can also decode a PNG saved by the transmitter.

The camera is off. Start it, play the sequence on the transmitter screen, and align the code with the frame.
Camera access requires a secure context (HTTPS or localhost) and browser permission. Keep the code upright, well lit, and fully inside the frame. Start with 81 × 81 or 121 × 121 for camera scanning; 161 × 161 and 201 × 201 grids require the code to occupy more screen pixels. The receiver attempts to detect the four Q4R1 corner markers and correct perspective; if it cannot detect them, move the camera closer and keep the entire code in view.
